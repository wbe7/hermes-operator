# Транскрибация агента (STT)

Дата: 2026-10-05. Статус: контракт подтверждён пользователем; реализация и расширение
allowlist существующего тестового ключа разрешены 2026-10-05.

Продолжение [исходного интервью](interview.md). Сохраняются границы неизменённого
upstream Hermes, namespace-local Secret references и восстановления управляемой
конфигурации при запуске без потери персонализации и пользовательского состояния.

## Требования из запроса

- Добавить основные параметры STT в типизированную секцию CR.
- Минимальная настройка: включить транскрибацию и указать отдельную STT-модель.
- Неуказанные STT base URL и API key наследуются из секции основной модели.
  Явные настройки STT имеют приоритет; URL и ключ разрешаются независимо.
- API key задаётся ссылкой на Secret, а не открытым значением в CR.
- Smoke: существующий `hermes-smoke` в `berger-apps`, endpoint
  `https://inference.s2technologies.ru/v1`, модель `qwen3-asr-1.7b`,
  существующий ключ LiteLLM. Пользовательские данные сохраняются.

## Проверенные предпосылки

Подробные источники и граница проверки: [STT в pinned Hermes](../research/stt-2026-10-05.md).

- В текущем API отдельной типизированной секции STT нет. Дополнительные настройки
  upstream сейчас могут задаваться через `extraConfig` и `credentials.env`;
  переход к новой секции требует явного решения о совместимости.
- Read-only проверка живого CR подтвердила Hermes `v2026.9.14`, основную модель
  `qwen38-27b` и требуемый endpoint. Основной ключ разрешается из
  `hermes-smoke-hermes-secret/MODEL_API_KEY`; значение не выводилось и не сохранялось
  в документации.
- `GET /v1/models` с этим ключом ответил HTTP 200, но не перечислил
  `qwen3-asr-1.7b`. Последующий `POST /v1/audio/transcriptions` с короткой
  синтетической русской речью получил HTTP 403 `key_model_access_denied`:
  существующему ключу разрешены `qwen38-27b`, `qwen38-27b-xhigh`,
  `qwen3-embedding-8b`. Перед успешным smoke нужно добавить `qwen3-asr-1.7b`
  в его allowlist; новый ключ для этого не требуется. Права не изменялись.

## Принятые ответы

- Q1: отсутствие секции или отсутствие явного `enabled: true` означает выключенный
  STT. Управляемое отключение должно перекрывать старый STT config и legacy aliases
  при запуске. Ручные настройки через прежний `extraConfig` потребуется перенести;
  эту несовместимость нужно описать в upgrade notes до rollout.
- Q2: язык по умолчанию — русский (`ru`), а не предложенное автоопределение.
  CR должен позволять переопределить язык; точное представление автоопределения
  будет описано в контракте с учётом поведения upstream.
- Q3: сохраняется штатное поведение Hermes. Голосовые сообщения автоматически
  транскрибируются; загруженный аудиофайл остаётся файлом для обработки агентом.
  Автоматизация любых вложений и изменение upstream не входят в это расширение.
- Q4: поддерживаются наследование авторизации LLM, отдельная ссылка на Secret
  и явный режим `None`. Пользователь уведомлён, что неизменённый SDK может
  отправлять служебный непустой Bearer вместо реального ключа.
- Q5: распознанный текст показывается в чате по умолчанию; поле
  `echoTranscripts` позволяет отключить показ.

## Предлагаемый итоговый контракт

Это подтверждённая инженерная конкретизация принятых ответов. Описание не
означает, что поля уже доступны в опубликованном CRD.

### Основные поля

Минимальный вариант для согласованного smoke:

```yaml
spec:
  stt:
    enabled: true
    model: qwen3-asr-1.7b
```

| Поле `spec.stt` | Предлагаемая семантика |
| --- | --- |
| `enabled` | По умолчанию false, включая отсутствие секции |
| `model` | Непустое имя модели, обязательно при включённом STT; не наследуется от LLM |
| `baseURL` | Явный абсолютный HTTP(S) URL либо наследование `spec.model.baseURL`; без credentials/query/fragment |
| `auth` | `Inherit` по умолчанию, либо `APIKey`, либо `None` |
| `apiKeySecretRef` | Необязательная ссылка на Secret в namespace инсталляции; имя при пропуске — основной Secret, ключ при пропуске — `STT_API_KEY` |
| `language` | По умолчанию `ru`; явный код языка либо `auto` для автоопределения |
| `echoTranscripts` | По умолчанию true; false отключает показ расшифровки перед ответом агента |

Поддерживается внешний OpenAI-compatible transcription API. Типизированные
варианты локальных моделей, произвольных STT plugins и TTS не добавляются в это
расширение. Название upstream provider `openai` обозначает протокол подключения,
а не обязательное обращение к инфраструктуре OpenAI.

### Независимое наследование URL и авторизации

- URL выбирается как явный `stt.baseURL`, иначе `model.baseURL`.
- `Inherit` без STT Secret reference наследует способ авторизации основной модели
  и, при APIKey, её эффективную ссылку на Secret, включая нестандартные имя и ключ.
- Явная `stt.apiKeySecretRef` при `Inherit` выбирает APIKey и имеет приоритет над
  настройками основной модели, даже когда сама LLM работает без ключа.
- `APIKey` с явной ссылкой использует её. Без ссылки он наследует LLM credential,
  только если у LLM включена APIKey-авторизация; иначе требуется явная ссылка STT.
- `None` не использует реальный STT/LLM ключ и несовместим с `apiKeySecretRef`.
  Runtime использует непустое служебное значение для совместимости с SDK;
  сервер должен игнорировать такой Authorization header.
- Если явный Secret/key отсутствует или пуст, это ошибка зависимости. Оператор
  не откатывается на основной ключ и не изменяет содержимое исходного Secret.
- URL и ключ наследуются независимо: при изменении только URL тот же LLM-ключ
  будет отправляться новому адресу. CR редактирует доверенная управляющая сторона;
  это следствие запрошенного правила приоритетов нужно явно показать в README.

### Жизненный цикл и совместимость

- Параметры STT — управляемая конфигурация: CR/Secret восстанавливают их при
  каждом запуске; пользовательское состояние на PVC сохраняется.
- Изменение эффективного STT config или используемого Secret создаёт новую
  runtime revision и перезапускает Pod по существующим правилам оператора.
- Отключённый STT не требует отдельного Secret и не должен проверять его наличие.
  Базовые ограничения формы полей продолжают действовать.
- Удаление секции или `enabled: false` восстанавливает явное выключение, включая
  старый `stt_enabled`. Это настройка штатного Hermes, а не запрет пользователю
  запускать собственные инструменты из workspace.
- Typed поля и aliases нельзя перекрыть через `extraConfig`, `extraEnv` или
  `credentials.env`; конфликт получает понятную ошибку. Дополнительные
  неконфликтующие STT параметры могут оставаться в `extraConfig`, если они
  поддерживаются закреплённой версией upstream.
- Для `language: auto` runtime записывает пустые языковые подсказки и очищает
  конфликтующий env, поскольку upstream не понимает буквальное значение `auto`.
- Сетевые исключения остаются явными настройками CR. STT URL не даёт
  автоматического разрешения на private IP.
- Оператор проверяет форму конфигурации и наличие credentials, но не опрашивает
  удалённый inference при каждом reconcile. Ошибка STT не должна объявлять
  неработоспособной всю исправную инсталляцию.
- Штатный локальный fallback Hermes и фиксированные upstream ограничения
  документируются; скрытые патчи для их изменения не вводятся.

1. API/defaults/валидация: включение, выключение, `ru`/`auto`, echo, все режимы
