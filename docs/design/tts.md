# Синтез речи агента (TTS)

Дата: 2026-10-06. Статус: контракт и реализация со smoke подтверждены пользователем 2026-10-07.

## Запрос

Добавить декларативную настройку TTS в оператор. Для smoke пользователь предложил
S2 Pro, уже настроенную в LiteLLM. Live read-only проверка нашла alias
`fish-s2-pro`. Read-only проверка ключа подтвердила отсутствие доступа к этой модели;
реальный синтез пока не проверен.

Сохраняются прежние границы проекта: неизменённое ядро Hermes, credentials
в namespace-local Secrets, восстановление управляемых настроек при запуске и
сохранение персонализации, файлов и истории на PVC.

## Дерево решений

| Ветвь | Состояние |
| --- | --- |
| Отсутствие spec.tts | Q1: подтверждено явное выключение без spec.tts |
| Подключение и авторизация | Q2: подтверждены наследование LLM, независимые URL/key overrides и auth None |
| Когда агент отвечает голосом | Q3: подтверждены все три режима; default — ответы на входящие голосовые |
| Изменение режима через /voice | Q4: подтверждено восстановление режима из CR при рестарте |
| Голос | Q5: обязательный voice; для smoke default; регистрация/клонирование вне scope |
| Скорость и язык | Q6: speed 1.0, диапазон 0.25–4; language опционален, без default |
| Доставка | Q7: штатные аудио + текст, при ошибке синтеза — текст |
| Выключение и восстановление старых настроек | Исследованы toolset, auto_tts и persisted chat modes; native migration tests обязательны |
| Smoke | Существующий тестовый Hermes; отдельно native synthesis и реальная доставка в Telegram |

Вопросы и предложения не являются утверждённым контрактом. Реализация начнётся
после согласования итогового поведения.

## Предварительные факты (анализ live upstream, не runtime smoke)

- OpenAI-compatible TTS принимает model/base_url/api_key/voice/speed/language.
  Language передаётся через extra_body.lang_code; совместимость нужно проверить.
- Native TTS не проверяет tts.enabled. Одного флага в YAML недостаточно:
  проектирование выключения должно учитывать инструмент и автоматические ответы.
- Команда /voice сохраняет режимы off/voice_only/all отдельно для чата в
  gateway_voice_mode.json; они имеют приоритет над voice.auto_tts.
- В LiteLLM найден alias fish-s2-pro, без заданного route-level voice default.

## Итоговый контракт

```yaml
spec:
  tts:
    enabled: true
    model: fish-s2-pro
    voice: default
    responseMode: VoiceOnly
    speed: 1.0
    # language: ru  # только если сервер поддерживает lang_code; для S2 Pro не задаём
```

- Отсутствие секции или enabled=false выключает штатный TTS при запуске:
  инструмент синтеза не предоставляется агенту, автоматические голосовые ответы
  отключены. Это восстановление конфигурации, а не запрет на произвольный код
  пользователя или временную перенастройку работающего Hermes.
- model и voice обязательны при enabled=true. Оператор поддерживает существующий
  голос сервера по имени/ID, но не загружает reference audio и не управляет
  регистрацией или клонированием голосов.
- baseURL и apiKeySecretRef независимо наследуются от spec.model, если отсутствуют.
  Явный STT override на TTS не влияет. Auth соответствует STT: Inherit по
  умолчанию, APIKey, None; placeholder для SDK в None не означает гарантированное
  отсутствие HTTP Authorization. Явный отсутствующий Secret/key не имеет fallback.
- Явный TTS apiKeySecretRef без имени использует основной Secret инсталляции,
  без key — TTS_API_KEY. При отсутствии ref наследуются реальные name/key LLM.
  References остаются в namespace инсталляции; ротация учитывается reconciler.
- responseMode: OnRequest (без автоозвучки, инструмент доступен), VoiceOnly
  (default: автоматическое аудио только в ответ на входящее голосовое), All
  (автоматическое аудио для всех ответов). Автодоставка первой версии проверяется
  на Telegram; не обещается новый web voice UI или поддержка иных мессенджеров.
- /voice может менять текущий режим, но при рестарте восстанавливается CR.
  Для известных разрешённых Telegram DM/group chat IDs оператор восстанавливает
  штатное per-chat состояние Hermes; voice.auto_tts=true не заменяет VoiceOnly.
  Пользовательские файлы, персонализация и история сохраняются.
- speed — опциональный множитель 0.25–4, default 1.0. language — опциональная
  подсказка без default. Отсутствие language очищает прежнюю управляемую подсказку.
  Native Hermes передаёт её как lang_code; поддержка зависит от сервера.
  Для текущей S2 Pro поле не задаётся. Это не универсальное обещание поддержки
  стандартного OpenAI language/instructions.
- Формат доставки выбирает штатный Hermes. В Telegram короткий текст идёт
  подписью, длинный — отдельным сообщением; при сбое TTS остаётся текст.
- Управляемые TTS/voice поля защищаются от конфликтующих extraConfig/env,
  как STT. Старый managed Nous selection и старые голосовые режимы не должны
  переопределять CR. Нельзя использовать неизвестное имя provider как выключатель:
  upstream может перейти на Edge/NeuTTS.
- Ядро Hermes не изменяется. Если native API не позволяет реализовать согласованный
  режим в этих границах, ограничение выносится на обсуждение, а не скрыто патчится.

## Приёмка

1. CRD/controller validation, defaults, auth inheritance/overrides/None,
   Secret dependencies, rotation/revocation; отсутствие credentials в открытом
   config/status/logs.
2. Native HTTP fixtures с фактическими model/voice/speed/lang_code/endpoint/key,
   все три режима и отсутствие вызовов TTS при штатном выключении.
3. Migration с прежнего PVC: пустые секции, устаревшие настройки, persisted /voice,
   выключение/повторное включение; восстановление после рестарта без потери данных.
4. Реальный S2 Pro: валидный аудиофайл, корректный формат/длительность и разборчивый
   русский текст; отдельно native Hermes и сквозная доставка только в разрешённый
   @HermesOperatorK8SBot. Не подменять transport evidence прямым API-запросом.
5. Обновлённые README, reference, examples, migration/limits и отчёт с границами
   фактических проверок. Публикация stable release/cluster-wide rollout отдельно
   от разработки и тестирования smoke.

## Подготовка smoke

Текущий dedicated key `hermes-operator-development` не допускает `fish-s2-pro`.
В итоговый план требуется включить добавление только этой модели к существующему
ключу с сохранением прежних моделей и лимитов. До утверждения плана ключ не менялся.
