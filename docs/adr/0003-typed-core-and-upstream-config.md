# Основные настройки типизированы, дополнительные следуют upstream

Пользователь принял комбинированный API: основные платформенные настройки модели, Telegram, хранения, сети и запуска представлены явными полями CR, а остальные административные параметры Hermes доступны через дополнительный объект конфигурации. Это сохраняет понятный Kubernetes API и позволяет использовать дополнительные возможности upstream без ручного копирования всей его схемы в каждом выпуске оператора.

Дополнительный объект внутри CR не переопределяет его основные поля и ограничения: конфликт явно отклоняется. Это правило сборки эталонного startup config, а не запрет пользователю менять работающий Hermes. Документация должна описывать типы, defaults, ссылки на Secrets, mapping в upstream, правила конфликтов и влияние изменений на перезапуск. Названия полей и список базовых настроек зафиксированы в [спецификации v1alpha1](../design/v1alpha1.md); её реализация и проверка следуют отдельно.

По уточнению пользователя SOUL и персональные инструкции не становятся принудительно управляемыми полями CR. `extraConfig` также не должен превращаться в обход этого разделения: персонализация остаётся пользовательской и сохраняется независимо от reconcile.
