# Конфигурация CR восстанавливается при запуске, персонализация сохраняется

Custom resource и указанные в нём Secrets задают эталонные параметры запуска Hermes: модель/provider/endpoint, reasoning, подключение Telegram и другие административные настройки. По последнему уточнению пользователя runtime config может быть writable: изменения внутри агента допустимы и восстанавливаются из CR/Secrets при следующем запуске.

SOUL, личность, пользовательские инструкции, память, skills, workspace, история и прочее пользовательское состояние сохраняются на PVC. Восстановление затрагивает только объявленные оператором настройки и связанные с ними runtime overrides; оно не заменяет целиком пользовательский home/config и не сбрасывает первичную персональную настройку.

Выбрана простая схема startup reconciliation вместо read-only config, managed overlay и запрета команд изменения модели. Применение должно выполняться перед каждым запуском контейнера, включая restart внутри существующего Pod; один initContainer эту задачу не решает. Сетевые политики, ограничения привилегий и другие Kubernetes-настройки действуют постоянно и не ослабляются из-за writable конфигурации Hermes. Точный безопасный merge и сохранность данных требуют runtime-проверки.
