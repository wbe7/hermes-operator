# TTS Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline, with one fresh whole-branch review at the end.

**Goal:** Declarative OpenAI-compatible TTS with retained personal state.
**Architecture:** Typed CR, resolved credential bindings and immutable startup input; pinned native Hermes remains unchanged. Bootstrap restores per-chat voice modes and managed configuration.
**Tech Stack:** Go/controller-runtime, CRD CEL, Python bootstrap, Helm, pinned Hermes.
**Spec:** docs/design/tts.md

## Global Constraints

TTS off without explicit opt-in; model/voice required; independent LLM URL/key inheritance; Inherit/APIKey/None; speed 1.0 (0.25–4); optional language without default, native lang_code semantics. Modes OnRequest/VoiceOnly/All, VoiceOnly default; CR resets /voice at restart. No upstream edits. Dedicated existing smoke only, no other Telegram chats. Preserve PVC contents. Stable merge/release/cluster-wide rollout excluded from this development step.

## Review Focus

Stale per-chat voice modes, disabled tool availability vs automatic speech, null config migration, keyless/explicit missing-key isolation, unsupported server parameters and invalid speed values.
